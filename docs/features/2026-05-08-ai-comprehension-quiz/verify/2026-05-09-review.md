### 4g. Polish gap found and fixed

**Gap:** `ThemesCoveredPanel.vue` was unit-tested in T32 (13 component tests pass) but never imported by `QuizTab.vue` or `ActiveSession.vue` — the panel was unreachable in the live app despite having a working chip-extraction heuristic and `seed-theme` event contract. `themes-covered` `data-test` attribute was missing from the production bundle.

**Spec impact:** breaks **FR-63** ("ThemesCoveredPanel emits seed-theme on chip click which updates `ScopePicker.theme`") and **FR-90/FR-94** (themes-summary UI surface).

**Fix (this verify pass):**
- `QuizTab.vue` now imports `ThemesCoveredPanel`, mounts it in `mode='ready'` alongside `ScopePicker` + `PastQAPanel`, plumbs `themesSummary` from `bookState.themesSummary` (store), listens for `@seed-theme`, stores in `seededTheme: ref<string|null>`.
- `ScopePicker.vue` accepts a new optional `seededTheme: string|null` prop; a `watch` on the prop sets the local `theme` ref so the chip click flows into the input.
- Added regression test `QuizTab.spec.ts > "mounts ThemesCoveredPanel in ready mode when lifetime themes_summary is present (FR-63 wiring)"`.

**Re-verification:**
- `npx vitest run` → **668 passed** (was 667; +1 regression test).
- `npm run build` re-ran clean.
- BookOverviewView chunk now contains `themes-covered` data-test (live grep: 1 match).
