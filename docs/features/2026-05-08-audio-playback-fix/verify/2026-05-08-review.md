## Known issues / Follow-ups (not blocking)

These are pre-existing latent issues surfaced during review but not introduced by this fix. Not required for the audio-playback fix to ship; flagged for a future cleanup pass:

1. **`AnnotationCard.vue` hardcodes `:book-id="0"`** — Should thread the parent's `book.id` through if annotation playback is ever wired to backend persistence. Today it's safe because annotation-content-type goes only through `preloadCache`, never `store.open()`.
2. **`ResumeAffordance.vue` calls `store.open()` without `engine.load()`** — Pre-existing on `main`. Component currently has no live parent (only test mounts). If/when re-introduced, the consumer must also call `engine.load()` (similar to TtsPlayButton.onClick) or the player would stick at `'loading'`.
3. **AppShell global Space-key handler crashes when `event.target === document`** — Pre-existing pattern outside this fix's scope. Real keypresses target focused elements, not document, so users don't hit this. Worth a one-line guard in a follow-up.
4. **Watchdog can fire as a false-positive on rapid Pause→Next** — Not a regression; matches spec E10's documented intent ("surfacing the error is correct"). Retry path recovers cleanly. If false positives become noisy in real use, plan's risk register suggests raising threshold from 1000ms to 1500ms — change one constant.
