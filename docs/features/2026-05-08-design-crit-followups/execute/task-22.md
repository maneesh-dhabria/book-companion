# T22: Playbar timestamp + tooltip (FR-E01, FR-E03)

## Outcome
- **Timestamp gate (FR-E01):** Existing `0:00 / 0:00` span tagged `data-testid="timestamp"` and gated `v-if="store.engine !== 'web-speech'"`. Hidden on Web Speech (which can't seek/scrub so the timestamp is meaningless), shown on the `mp3` engine (Kokoro precomputed playback).
- **Limited-controls tooltip (FR-E03):** The existing `chip chip--warn "Limited controls"` is now wrapped in a `.limited-wrap` span (`tabindex="0"` for keyboard reach, `position: relative`). A sibling `role="tooltip"` element with `data-testid="limited-controls-tooltip"` shows on `:hover` / `:focus-within`: `Web Speech can't seek/scrub. <a href="/settings#audio">Install Kokoro for full controls →</a>`. CSS handles fade in/out via opacity + pointer-events.

## Plan deviations
- Plan §T22 step 2 said `v-if="store.engine === 'kokoro'"`, but `TtsEngineKind` is `'mp3' | 'web-speech'` — the Kokoro engine identifies as `'mp3'` at runtime (it plays precomputed MP3 files generated by Kokoro). Used `engine !== 'web-speech'` instead, which is more robust against future engine kinds.
- Plan §T22 step 3 said reuse the `TtsPlayButton` tooltip pattern. `TtsPlayButton.vue` doesn't define a tooltip component (only uses `title` attributes); `EngineChip.vue` is the actual tooltip-pattern source — but its tooltip is `sr-only` (screen-reader only), unsuitable here. Implemented a visible CSS-only hover/focus tooltip inline (~25 lines of scoped CSS). No new shared tooltip primitive — the spec only needs this once.
